This document details a compressed PLY specification optimized for 3D Gaussian Splatting, as introduced by PlayCanvas. The primary goal of this format is to significantly reduce file size while maintaining visual fidelity by employing a chunk-based quantization scheme.

### 1. Overview of the Compressed PLY Format

The compressed PLY format for Gaussian Splats leverages two main techniques:
1.  **Chunking:** The entire set of Gaussian splats is divided into smaller groups, referred to as "chunks." Each chunk contains a fixed number of splats (typically 256).
2.  **Quantization:** Within each chunk, the data for individual splats (position, scale, color, rotation) is compressed by:
    *   Determining the minimum and maximum values for certain properties (like position coordinates or scale factors) across all splats within that chunk.
    *   Storing these min/max bounds as high-precision floating-point numbers in a dedicated `chunk` element.
    *   Then, for each splat, storing its individual properties as a low-precision, normalized value relative to the chunk's bounds. These normalized values are packed into 32-bit (or 8-bit for SH) integers.

This approach allows for precise reconstruction of the original values by interpolating between the chunk's bounds using the stored normalized splat data.

### 2. PLY Header Structure

The header for a compressed PLY file follows the standard PLY format, with specific elements defining the chunk, vertex, and optional spherical harmonics data.

```
ply
format binary_little_endian 1.0
comment Generated by [Tool Name/Version]
element chunk <number_of_chunks>
property float min_x
property float min_y
property float min_z
property float max_x
property float max_y
property float max_z
property float min_scale_x
property float min_scale_y
property float min_scale_z
property float max_scale_x
property float max_scale_y
property float max_scale_z
property float min_r
property float min_g
property float min_b
property float max_r
property float max_g
property float max_b
element vertex <number_of_splats>
property uint packed_position
property uint packed_rotation
property uint packed_scale
property uint packed_color
element sh <number_of_splats>   (Optional)
property uchar f_rest_0
property uchar f_rest_1
...
property uchar f_rest_N        (where N depends on the SH band level)
end_header
```

### 3. Element Specifications

#### 3.1. `chunk` Element

This element stores the bounding box and value ranges for each chunk of splats. There is one `chunk` entry for every group of 256 splats.

*   **Number of Elements:** `number_of_chunks = ceil(total_number_of_splats / 256)`
*   **Properties (all `float32`):**
    *   `min_x`, `min_y`, `min_z`: Minimum world-space coordinates of all splats within this chunk.
    *   `max_x`, `max_y`, `max_z`: Maximum world-space coordinates of all splats within this chunk.
    *   `min_scale_x`, `min_scale_y`, `min_scale_z`: Minimum scale components (exponentiated) of all splats within this chunk.
    *   `max_scale_x`, `max_scale_y`, `max_scale_z`: Maximum scale components (exponentiated) of all splats within this chunk.
    *   `min_r`, `min_g`, `min_b`: Minimum DC color components of all splats within this chunk, after conversion from Spherical Harmonics (e.g., in the 0-1 range).
    *   `max_r`, `max_g`, `max_b`: Maximum DC color components of all splats within this chunk.

#### 3.2. `vertex` Element

This element stores the compressed, packed data for each individual Gaussian splat. The properties are 32-bit unsigned integers, where multiple values are bit-packed into a single integer.

*   **Number of Elements:** `total_number_of_splats`
*   **Properties (all `uint32`):**

    *   **`packed_position`**: Stores the normalized (0-1 range) x, y, and z positions of the splat relative to its chunk's `min`/`max` bounds.
        *   **Bit Allocation:**
            *   `x`: 11 bits (Most significant bits)
            *   `y`: 10 bits
            *   `z`: 11 bits (Least significant bits)
        *   **Decompression:** The packed integer is parsed, each component is converted back to a `float` in the 0-1 range (e.g., `value / ((1 << bits) - 1)`), and then linearly interpolated between the chunk's `min_x`/`max_x`, `min_y`/`max_y`, `min_z`/`max_z` values.

    *   **`packed_rotation`**: Stores the compressed representation of the splat's rotation quaternion (x, y, z, w). The largest component of the quaternion is not stored directly but is inferred during decompression.
        *   **Bit Allocation:**
            *   `largest_component_index`: 2 bits (Most significant bits) - Indicates which of the x, y, z, w components had the largest absolute value.
            *   `component_0`: 10 bits
            *   `component_1`: 10 bits
            *   `component_2`: 10 bits (Least significant bits)
        *   **Decompression:** The three stored 10-bit components are unpacked and converted to a normalized float in a specific range (e.g., -0.707 to 0.707). The fourth (largest) component is then reconstructed using the property that a unit quaternion's components sum to 1 squared (i.e., `x^2 + y^2 + z^2 + w^2 = 1`). The `largest_component_index` tells which position to place the reconstructed component.

    *   **`packed_scale`**: Stores the normalized (0-1 range) x, y, and z scale values of the splat relative to its chunk's `min_scale`/`max_scale` bounds.
        *   **Bit Allocation:**
            *   `x`: 11 bits (Most significant bits)
            *   `y`: 10 bits
            *   `z`: 11 bits (Least significant bits)
        *   **Decompression:** Similar to `packed_position`, each component is unpacked, converted to a 0-1 float, and then linearly interpolated between the chunk's `min_scale_x`/`max_scale_x`, etc., values. The resulting values are typically in the exponentiated scale space (e.g., `exp(s)`), matching the input format of many Gaussian Splat renderers.

    *   **`packed_color`**: Stores the normalized (0-1 range) red, green, blue color components and the opacity (alpha) of the splat.
        *   **Bit Allocation:**
            *   `red`: 8 bits (Most significant bits)
            *   `green`: 8 bits
            *   `blue`: 8 bits
            *   `opacity`: 8 bits (Least significant bits)
        *   **Decompression:** Each 8-bit component is unpacked and converted to a `float` in the 0-1 range.
            *   For Red, Green, Blue: These 0-1 values are linearly interpolated between the chunk's `min_r`/`max_r`, etc., values. These de-quantized color values often represent the *diffuse color* component `f_dc` in Gaussian Splatting, which then needs to be divided by `SH_C0` (0.28209479177387814) to obtain the original `f_dc` coefficients.
            *   For Opacity: The 0-1 value represents a normalized opacity. This typically needs to be converted into the original logit-space opacity (`-log(1/alpha - 1)`) for rendering.

#### 3.3. `sh` Element (Optional)

This element stores additional spherical harmonics coefficients, if present. The number of coefficients (`N`) determines the spherical harmonic band level (e.g., 9 coeffs for L1, 24 for L2, 45 for L3).

*   **Number of Elements:** `total_number_of_splats`
*   **Properties (all `uchar` - unsigned 8-bit integer):**
    *   `f_rest_0`, `f_rest_1`, ..., `f_rest_N`: These are quantized spherical harmonic coefficients for bands beyond the DC (L0) component.
    *   **Decompression:** Each 8-bit `uchar` value (0-255) is converted back to a floating-point representation. A common mapping is to normalize the 8-bit integer to a 0-1 range (e.g., `(value + 0.5) / 256` for values 1-254, 0 for 0, 1 for 255), and then map it to a specific float range (e.g., `(normalized_value - 0.5) * 8`) to recover the original SH coefficient values.

### 4. Compression Process (Conceptual)

1.  **Scene Ordering:** Gaussian splats are typically reordered (e.g., using Morton order) to improve cache coherence and potentially chunk compression efficiency.
2.  **Chunk Definition:** The sorted splats are divided into chunks of 256.
3.  **Chunk Data Calculation:** For each chunk:
    *   Iterate through all splats in the chunk.
    *   Determine the `min_x`, `max_x`, `min_y`, `max_y`, etc., for position, scale (exponentiated), and DC color components.
    *   Store these `float32` values in the `chunk` element data.
4.  **Vertex Data Quantization and Packing:** For each splat within a chunk:
    *   **Position:** Normalize the splat's x, y, z positions to a 0-1 range using the chunk's `min`/`max` bounds (e.g., `(value - min_val) / (max_val - min_val)`). Quantize these normalized floats into 11, 10, and 11 bits respectively, and pack them into a `uint32` for `packed_position`.
    *   **Rotation:** Identify the largest component of the splat's quaternion. Normalize the other three components into a specific range. Store the index of the largest component (2 bits) and the quantized values of the other three (10 bits each) into a `uint32` for `packed_rotation`.
    *   **Scale:** Similar to position, normalize and quantize the splat's scale (exponentiated) components based on the chunk's `min_scale`/`max_scale` bounds, packing into a `uint32` for `packed_scale`.
    *   **Color & Opacity:** Convert the splat's DC color coefficients to 0-1 range (e.g., `f_dc * SH_C0 + 0.5`). Normalize these color components based on the chunk's `min_r`/`max_r` bounds. Convert the splat's opacity to a 0-1 normalized range (e.g., `1 / (1 + exp(-opacity_value))`). Quantize each of these 0-1 values into 8 bits and pack them into a `uint32` for `packed_color`.
5.  **Spherical Harmonics Quantization (Optional):** For each `f_rest_X` coefficient, normalize it to a 0-1 range (e.g., `f_rest_X / 8 + 0.5`) and then quantize to an 8-bit unsigned integer (0-255).
6.  **File Writing:** Construct the PLY header with the appropriate element counts. Write the header, followed by the binary `chunk` data, then the binary `vertex` data, and finally the optional `sh` data.

### 5. Decompression Process (Conceptual)

1.  **Read Header:** Parse the PLY header to understand the data layout, element counts, and property types.
2.  **Read Chunk Data:** Load all `chunk` elements into memory.
3.  **Read Vertex Data:** Load all `vertex` elements into memory.
4.  **Read SH Data (Optional):** Load all `sh` elements if they exist.
5.  **Reconstruct Splat Data:** Iterate through each splat's `packed_` properties:
    *   **Determine Chunk:** Based on the splat's index, identify which chunk it belongs to (e.g., `chunk_index = floor(splat_index / 256)`).
    *   **Retrieve Chunk Bounds:** Get the `min`/`max` values for position, scale, and color from the corresponding `chunk` element.
    *   **Unpack and De-quantize Position:** Unpack the `packed_position` `uint32` into its 11-bit x, 10-bit y, and 11-bit z components. Convert each component to a normalized `float` (0-1). Linearly interpolate these normalized values using the chunk's `min_x`/`max_x`, `min_y`/`max_y`, `min_z`/`max_z` to get the original `float32` x, y, z positions.
    *   **Unpack and De-quantize Rotation:** Unpack the `packed_rotation` `uint32` into the 2-bit largest component index and the three 10-bit components. Convert the 10-bit components to their normalized `float` values. Using the largest component index, reconstruct the full 4-component `float32` quaternion.
    *   **Unpack and De-quantize Scale:** Similar to position, unpack `packed_scale`, convert to normalized floats, and linearly interpolate using the chunk's `min_scale_x`/`max_scale_x`, etc., to get the original `float32` scale components (exponentiated).
    *   **Unpack and De-quantize Color & Opacity:** Unpack the `packed_color` `uint32` into its 8-bit R, G, B, and Opacity components. Convert each to a normalized `float` (0-1).
        *   For R, G, B: Linearly interpolate using the chunk's `min_r`/`max_r`, etc. Then, convert these values (which are usually in a 0-1 range, often `(f_dc * SH_C0 + 0.5)`) back to the original `f_dc` coefficients (e.g., `(dequantized_color - 0.5) / SH_C0`).
        *   For Opacity: Convert the 0-1 normalized opacity back to its original logit space value (e.g., `-log(1 / normalized_opacity - 1)`).
    *   **De-quantize Spherical Harmonics (Optional):** For each `f_rest_X` `uchar`, convert it back to its original `float32` value (e.g., `(normalized_value - 0.5) * 8`).
6.  **Store Decompressed Data:** Collect all reconstructed `float32` values for position, rotation, scale, color, opacity, and spherical harmonics into the desired output data structure.
